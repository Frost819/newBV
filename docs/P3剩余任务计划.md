### A. 弹幕分段加载（双通道）★核心

#### A.1 接口对照

| 通道 | 端点 | 鉴权 | 响应 |
|---|---|---|---|
| Web HTTP | `GET /x/v2/dm/wbi/web/seg.so` | SESSDATA Cookie + **WBI**（路径含 `wbi`，现有 `encApiSign()` 自动签名） | protobuf `DmSegMobileReply` |
| App gRPC | `DM.DmSegMobile` | gRPC metadata（access_token 等，现有 Channel） | 同一 `DmSegMobileReply` |
| （旧，本轮停用主路径） | `GET /x/v1/dm/list.so` | 无签名 XML 全量 | `DanmakuResponse` |

文档参数（`danmaku_proto.md`）：

| 参数 | 值 | 说明 |
|---|---|---|
| type | 1 | 视频弹幕 |
| oid | cid | 必要 |
| pid | avid | Web 必要（文档标非必要，fork 始终传） |
| segment_index | 从 1 开始 | 6 分钟一包；单包最多 6000 条；progress 值域 `[0, 360000)` ms |

半匿名：无 SESSDATA 时部分视频只返回部分弹幕（文档明示，属预期）。

旧 XML 接口 `getDanmakuXml` **保留**作 fallback 代码，本轮主路径不再调用。不自动降级。

#### A.2 bili-api 改动

**1. `BiliHttpApi.getDanmakuSeg`**

```kotlin
/**
 * 获取视频弹幕分段（Web protobuf 接口）。
 *
 * 对应文档：docs/bilibili-API-collect-master/docs/danmaku/danmaku_proto.md
 * 端点：GET /x/v2/dm/wbi/web/seg.so（WBI 由 encApiSign 拦截器自动签名）
 * 鉴权：SESSDATA Cookie（injectCookies）；半匿名时返回部分弹幕
 *
 * @param cid 视频 CID（oid）
 * @param avid 稿件 avid（pid）
 * @param segmentIndex 分段索引，从 1 开始，每 6 分钟一段
 */
suspend fun getDanmakuSeg(
    cid: Long,
    avid: Long,
    segmentIndex: Int,
): List<DanmakuData>
```

实现要点（对齐 fork，修正其 bug）：

- `client.get("/x/v2/dm/wbi/web/seg.so")` + `type=1` / `oid` / `pid` / `segment_index`
- `readRawBytes()` → `DmSegMobileReply.parseFrom(bytes)`
- 字段映射：

| proto `DanmakuElem` | `DanmakuData` | 注意 |
|---|---|---|
| `progress` | `time = progress / 1000f` | 毫秒 → 秒 |
| `mode` | `type` | |
| `fontsize` | `size` | |
| `color` | `color` | |
| `ctime` | `timestamp = ctime.toInt()` | **fork 误写成 `/1000`，ctime 文档已是秒** |
| `pool` | `pool` | |
| `midHash` | `midHash` | |
| `id` | `dmid` | |
| `weight` | `level` | 智能屏蔽权重 0–10 |
| `content` | `text` | |

**2. `VideoPlayRepository.getDanmakuSegment`**

```kotlin
/**
 * 获取弹幕分段。Web / App 显式分离，失败直接抛错，不自动切换通道。
 *
 * @param preferApiType 必须显式传入，无默认值
 */
suspend fun getDanmakuSegment(
    aid: Long,

    segmentIndex: Int,

```

- `ApiType.Web` → `BiliHttpApi.getDanmakuSeg`

抽出 `DanmakuData.fromDanmakuElem(elem)`（或独立 mapper），两通道共用。

**3. `DanmakuViewModel` 不再直调 `BiliHttpApi`**

加载一律走 Repository，与项目 UDF / DI 规范对齐。

#### A.3 DanmakuViewModel 分段缓存

常量：

```kotlin
private const val SEGMENT_DURATION_MS = 6 * 60 * 1000L  // 360_000
```

段索引：`segmentIndex = (positionMs.coerceAtLeast(0) / SEGMENT_DURATION_MS).toInt() + 1`

**驱动方式（强制响应式，禁止 while+delay）**：

监听 `PlayerViewModel.seekerState.currentTime`（或 UI 层把 `currentTime` 以参数/`SharedFlow` 传给 DanmakuViewModel——优先 ViewModel 间不互相注入，由 `VideoPlayerScreen` 协调）：

```
currentTime
  → map { it / 360_000L + 1 }          // 当前段
  → 同时请求当前段与当前段+1            // 预取下一包，对齐 fork 的 15s 提前量意图
  → distinctUntilChanged(目标段集合)
  → collectLatest { loadMissing(it) }
```

协调方式二选一（实现时选更小改动）：

1. **推荐**：`VideoPlayerScreen` 已有 `LaunchedEffect` 同步弹幕 play/pause/seek；新增对 `seekerState.currentTime` 的 `map/distinctUntilChanged` 调用 `danmakuViewModel.ensureSegments(positionMs)`
2. DanmakuViewModel 暴露 `fun onPosition(positionMs: Long)`，由现有 100ms UI 重组或专门 LaunchedEffect 节流调用（内部再 distinct 段索引）

**已加载记录**：`MutableMap<Int, Int>`（段索引 → 条数）

- 已存在则跳过
- 失败 **remove** 该 key，后续自然重试（对齐 fork）
- 切集 / `clearDanmaku`：清空 map、取消 in-flight、`updateData(emptyList())`

**seek**：现有 `seekTo` 同步链路里立刻 `ensureSegments(seekPosition)`，不等下一次 100ms tick。

**写入引擎**：ViewModel 持有累积 `List<DanmakuItemData>`，每到一段 append 后整体 `danmakuPlayer.updateData(accumulated)`（akdanmaku 无 append）。v1 **不淘汰已播段**（与 fork 一致）：完整播完内存峰值约等于旧全量，但启动延迟与瞬时解析压力下降。淘汰窗口（只保留 ±2 段）留作后续增强，不在本轮。

**切集**：沿用 `videoSwitchEvent` → `clearDanmaku` + `loadDanmaku(newCid)`。`loadDanmaku` 改为「记下 aid/cid，按当前进度拉段」，不再一次拉全量。需要 **aid**：当前 `loadDanmaku(cid)` 只有 cid，必须改为 `loadDanmaku(aid, cid)`。调用点：

- `PlayerScreens.kt`（直进播放器）
- `VideoPlayerScreen.kt`（`videoSwitchEvent`）

### D. 缩略图缓存 LRU 50MB

文件：`app/util/VideoShotExtends.kt` → `VideoShotImageCache`

现状：`LruCache<Int, Bitmap>(3)` 按 **条目数**。

改为按 **字节**：

```kotlin
private val memoryCache = object : LruCache<Int, Bitmap>(MAX_BYTES) {
    override fun sizeOf(key: Int, value: Bitmap): Int = value.byteCount
}
```

- `MAX_BYTES = 50 * 1024 * 1024`（PRD §5.2.3）
- 保留 RGB_565、`ConcurrentHashMap` 去重解码
- 切视频时清缓存（若尚未清）
- 确认绘制侧 `FilterQuality.Low`

测试：`VideoShotImageCacheTest`（单元，Robolectric 或纯 Bitmap mock）——超限淘汰最旧、命中不重复解码、并发同索引复用 task。

| WBI `seg.so` 触发风控 | A | 自然频率低（~6min/段 + seek）；失败静默、map 移除后重试；不轮换 UA |
| Web 切分段后弹幕变少 | A | 半匿名/低权限属文档行为；登录态对比旧 XML 做一次抽检 |
| App gRPC `DmSegMobile` 未登录不可用 | A | 遵循显式分离：App 模式失败就失败，不回落 Web |
| `updateData` 全量替换造成卡顿 | A | 段到达间隔长（分钟级）；若卡再改为增量 API 调研 |
| shrinkResources / R8 回归 | 7 | 冒烟 + keep 规则 |
| 冷启动 2s 在低端 TV 达不到 | B | 记录实测设备；优化能做的 IO，不牺牲 Prefs 首帧正确性 |
| LeakCanary 误报 | F | 确认引用链后再改，不盲拆单例 |
